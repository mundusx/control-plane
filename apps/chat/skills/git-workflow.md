# Git Workflow Skill

Purpose: manage project version control through approved MundusX repository tools.
- Inspect repository status before changing branches, committing, fetching, pushing, or merging.
- Initialize Git only inside the active project boundary and keep credentials out of prompts, files, responses, and logs.
- Commit only the files produced or approved by the current project task, using a concise factual message.
- Fetch before updating an existing remote project and use fast-forward-only updates; stop and explain divergent history.
- Push the current task branch unless repository policy explicitly permits the default branch.
- Create a pull request for reviewed work and treat remote merge as a separate user-authorized action.
- Never force-push, discard local changes, rewrite history, change remotes, or bypass protected-branch rules without an explicit permitted operation.
- Report the repository, branch, resulting commit, remote action, and any remaining local changes.
