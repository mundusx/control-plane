# Hosted Hermes web research

Optional coordination: set `WEB_RESEARCH_REDIS_URL` to a private, authenticated Redis URL. Without it, or when Redis is unavailable, the existing direct crawler runs with two local slots and no fallback cache or queue. No research storage is added to PostgreSQL. Deploy `apps/web-research-redis` with `REDIS_PASSWORD`, no volume and no public endpoint: snapshots and AOF are disabled, memory is capped at 128 MB, and keys expire automatically.

Redis coordinates two crawls across workers and a bounded, temporary queue (25-second wait, 64 pending jobs). Coordinated crawls have a 150-second runtime; direct crawls retain 180 seconds. Standalone public discovery questions share grounded results for five minutes. Case/spacing normalization handles exact variants; local BGE embeddings match paraphrases only above 0.92 cosine similarity and with the same topic/version/constraint words. This is intentionally conservative, not arbitrary meaning equivalence. Up to 128 recent candidates are compared. Embedding unavailability leaves exact matching operational. Context, URLs, private-language and freshness requests bypass shared caching. Matching inflight requests share one result. Redis outages during publication return the answer already obtained. An outage can cause duplicate crawls across instances, bounded by each instance's local slots.

`GET /cache/status` requires the worker bearer token and reports Redis connectivity, persistence settings and embedding readiness without exposing queries. Test Redis behavior with `python -m unittest discover -s apps/web-research -p 'test_*.py'` after installing `fakeredis[lua]==2.38.0` and `redis==8.1.0` in an isolated test environment.

Cache normalization handles Unicode width, case, whitespace, trailing sentence punctuation and introductory `who's`/`what's` contractions. Multi-word `who is` person questions also tolerate stray trailing underscores; Chat cleans these before biography routing and retrieval. Internal underscores, name spelling, word order, version numbers and technical punctuation remain significant. Arbitrary spelling mistakes are not silently merged into another person's identity. Cache namespace v2 isolates these revised matching rules from older entries, which expire naturally.

Ordinary Chat routes website questions and explicit web searches here without requiring a Project or personal device. The worker reads public HTML using Hermes' connect-time network protections, then falls back to Hermes extraction for unreadable pages. It retrieves evidence before asking the existing MundusX model to answer. It allows only web tools, runs each request in a fresh disposable Hermes profile, bounds concurrency and runtime, and retains retrieved excerpts if analysis fails. Website content is untrusted input. Private-network and credential-bearing extraction URLs are rejected.

Build this directory's Dockerfile. Hermes is pinned to a commit and installed with its frozen lockfile. Configure `WEB_RESEARCH_TOKEN`, `RESEARCH_MODEL_URL` (OpenAI-compatible base URL ending in `/v1`), `RESEARCH_MODEL_TOKEN`, and `RESEARCH_MODEL`. `PORT` defaults to 8080. Set Chat's `MUNDUSX_WEB_RESEARCH_URL` to the worker's private HTTP origin and `MUNDUSX_WEB_RESEARCH_TOKEN` to the same shared token. Never expose the token in browser code.

`GET /health` checks configuration. `POST /research` requires bearer authentication and accepts `{ "message": "Summarize this website", "urls": ["https://example.com"] }`; an empty URL list uses Hermes' DDGS web search provider. Search results may contain snippets rather than full pages. Firecrawl handles extraction fallback; anonymous access can be blocked. Set `FIRECRAWL_API_KEY` for additional extraction capacity. This is public page retrieval and research, not an authenticated interactive browser. Providers can rate-limit or fail; those failures remain visible to the user.

Deploy with `railway up apps/web-research --path-as-root --service hermes-web --detach` against the intended linked project. Chat is deployed separately. Do not enable the Chat URL until a real retrieval plus model answer succeeds. Routing intentionally excludes code examples and browsing opt-outs; ambiguous requests continue through ordinary Chat.

General factual questions search before answering, even when no current-time keyword or known product name appears. Two broad query variants discover candidates from diverse origins; up to three full pages are read before synthesis. Retrieved text and snippets are labeled separately. Hermes may use further web tools to cross-check uncertain claims. The answer cites up to three relevant retrieved sources rather than a fixed set of platforms. Failure to retrieve evidence is not evidence that a product or person does not exist.

Explicit profile follow-ups carry user-provided identity context, never earlier assistant biographies. There is no forced LinkedIn/GitHub/official-site checklist. Name matches and claims of being official are not proof of identity or authority. Coding examples, local-context tasks, weather lookups, and explicit browsing opt-outs retain their dedicated paths. Research adds network latency and cannot guarantee source accuracy; conflicts and uncertainty must remain visible.

Person-name lookups use quoted-name broad searches plus a LinkedIn discovery query. Results for different names are filtered before synthesis; person answers cannot launch unfiltered follow-on searches. If no identity-matching evidence remains, the worker asks for context without inferring nonexistence or a spelling error. LinkedIn evidence may be indexed snippets rather than a full profile.
